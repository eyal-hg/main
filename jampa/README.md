# Jampa — ממשק מטפלים

מותג שני על **אותו core בדיוק** של דשבורד HK: הפלטפורמה מתפצלת לשניים —
HK (פיננסי) ו-Jampa (טיפולי) — עם ליבה משותפת ושכבת מותג/פרסונה שונה.

פתיחה: `jampa/index.html` (ללא build, מ-`file://`).

## איך זה בנוי על הליבה המשותפת

| שכבה | מקור |
|---|---|
| CSS ליבה | `../css/base.css, dashboard, portfolio, ops, chat, meetings` — ללא שינוי |
| מיתוג | `css/theme.css` — מיפוי טוקנים לסגול/קרם Jampa + התאמות נקודתיות |
| לוגיקה | `js/` — מודולים באותו עיקרון (data / core / screens / record / meetings / chat / main) |

## ההקבלה המושגית ל-HK

| HK | Jampa |
|---|---|
| חברות | מטופלים |
| מנהל תזרים / יועץ / לקוח | מטפל / מטופל |
| מצב תפעול (טיימר, באנר) | **מצב הקלטה** (טיימר, `#rec` ב-URL, back מבטל) |
| סיום תפעול → בדיקות Bizibox | סיום הקלטה → עיבוד AI (תמלול, ניתוח, סיכום, סופרוויזיון) |
| שליחת תזרים ללקוח בוואטסאפ | שליחת סיכום אישי למטופל בוואטסאפ |
| מוקד התראות + מפת בריאות | מוקד טיפולי + מפת מטופלים (ספארקליין מצב רוח) |
| הכנה לפגישה | בריף 60 שניות (תמונת מצב / דפוסים / פתיחות) |

## מסכים

- **בית מטפל** — סטריפ מדדים, מפת מטופלים, "דורשים תשומת לב" (exception-driven), פגישות קרובות.
- **תיק מטופל** — KPI (התקדמות, מצב רוח, משימות, פגישה הבאה), טאבים: דשבורד / פגישות והקלטות / צ'אט וליווי / הכנה לפגישה.
- **מצב הקלטה** — כפתור "הקלט פגישה" → באנר סגול + טיימר → סיום → מודל עיבוד → סיכום + סופרוויזיון → שליחה בוואטסאפ (עם משך הפגישה).
- **מודל סיכום פגישה** — טאבים: סיכום / סופרוויזיון / משימות; אישור שולח למטופל.
- **פרסונת מטופל** — ללא rail, ללא הקלטה וללא בריף; רואה את המשימות שלו.

הכול דמה (אין חיבורים אמיתיים) — כמו פרוטוטייפ ה-HK.
