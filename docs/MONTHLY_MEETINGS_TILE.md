# משימה — שתי קוביות בפס "מצב היום" של מנהל התזרים

מסמך למתכנת ול-AI שלו. הפרוטוטיפ (`js/queue.js`, `renderOpsQueue` / `oqsPop`) הוא ההתנהגות
הרצויה; הצילום מצורף בשיחה.

**איפה בניווט:** תצוגת **מנהל תזרים** (בורר "תצוגה" בראש המסך) → המסך הראשי → פס "מצב
היום" למעלה, חמש קוביות: זמני תפעול · סטטוס תפעול · מסמכים להזנה · **פגישות חודשיות** ·
**דוחות חודשיים**. המשימה נוגעת לשתי האחרונות.

## מה משתנה

| | היום | אחרי המשימה |
|---|---|---|
| קובייה 4 | "הזנות ואוטומציה" | **"פגישות חודשיות"** — חדשה |
| קובייה 5 | "דוחות חודשיים" על כל הלקוחות, "נשלח" לא נרשם באמת | **רק לקוחות Money / Money+**, "נשלח" = רשומה בטבלה |

## 1 · פגישות חודשיות

**המונה `N / M`:**
- **M** = לקוחות פעילים עם מוצר **Money+** (`products.id = 4`).
- **N** = מתוכם, כמה עם פגישה שנקבעה החודש — לחברה קיימת שורה ב-`meetings` בחודש
  הנוכחי שעונה על:

```sql
status IN ('approve','processed')
OR (status = 'scheduled' AND scheduled_at >= CURRENT_DATE)
```

פגישה שאושרה או עובדה נספרת גם אם התקיימה; מתוכננת נספרת רק אם המועד עוד לפנינו;
מתוכננת שמועדה עבר בלי לעבור לעיבוד — לא נספרת.

**שורת המשנה:** "(M−N) בלי פגישה החודש".

**לחיצה על הקובייה** פותחת פירוט תחום בגובה (גלילה פנימית, לא פופאפ שגולש מהמסך):
- שורה לכל לקוח Money+: שם החברה, ותג מצב — **"לא נקבעה"** (אפור) או **"✓ נקבעה"** (ירוק)
  עם המועד כשורת משנה.
- מי שלא נקבעה — ראשונים; בתוך כל קבוצה לפי א-ב.
- לחיצה על שורה פותחת את מסך הפגישות של החברה. **אין כפתור "לתיאום" ואין פעולה בפירוט.**

## 2 · דוחות חודשיים

**המונה `N / M`:**
- **M** = לקוחות פעילים עם מוצר **Money או Money+** (`products.id IN (3, 4)`).
- **N** = מתוכם, כמה קיבלו את הדוח החודשי של החודש הנוכחי.

**איך יודעים שנשלח — טבלה חדשה, נכתבת בכל שליחה מהמסך:**

```sql
CREATE TABLE monthly_report_sends (
  id          BIGSERIAL PRIMARY KEY,
  company_id  BIGINT NOT NULL REFERENCES companies(id),
  month       DATE   NOT NULL,          -- החודש שהדוח מכסה (היום הראשון בחודש)
  sent_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
  sent_by     BIGINT NOT NULL,          -- המשתמש שלחץ "שליחת דוח"
  channel     TEXT NOT NULL DEFAULT 'whatsapp'
);
CREATE INDEX ON monthly_report_sends (company_id, month);
```

לקוח נספר כ"נשלח" אם יש לו שורה ל-`month` הנוכחי. שליחה חוזרת מוסיפה שורה (היסטוריה);
המונה סופר חברות, לא שורות.

**שורת המשנה:** "עד 10.7 · (M−N) נותרו" (10.7 = היעד לשליחת הדוחות החודשיים).

**לחיצה על הקובייה** פותחת פירוט תחום בגובה עם גלילה: שורה לכל לקוח, תג **"לא נשלח"**
(אפור) או **"✓ נשלח"** (ירוק); לא-נשלח ראשונים. לחיצה על שורה פותחת את כרטיס החברה.
**אין כפתור "שליחת דוח" בפירוט** — השליחה נעשית מהמקום הקיים במסך החברה, והיא זו שכותבת
את השורה לטבלה.

## 3 · API (סקיצה)

```
GET  /manager/monthly-meetings?month=YYYY-MM
← { total: M, scheduled: N, clients:[{company_id, name, scheduled:bool, when?}] }

GET  /manager/monthly-reports?month=YYYY-MM
← { total: M, sent: N, clients:[{company_id, name, sent:bool, sent_at?}] }

POST /companies/:id/monthly-report/send   {month}   ← שולח, וכותב שורה ל-monthly_report_sends
```

## 4 · קריטריונים לסיום

1. הקובייה הרביעית נקראת "פגישות חודשיות" ומראה `N / M` לפי הכלל ב-§1; "הזנות ואוטומציה" לא מופיעה.
2. "דוחות חודשיים" סופרת רק לקוחות עם מוצרים 3 ו-4.
3. שליחת דוח חודשי מהמסך יוצרת שורה ב-`monthly_report_sends`; המונה עולה מיד אחרי השליחה.
4. שני הפירוטים: גובה מוגבל עם גלילה, לא-נקבע / לא-נשלח ראשונים, בלי כפתורי פעולה.
5. לקוח בארכיון או בהקמה לא נספר באף אחת מהקוביות.
