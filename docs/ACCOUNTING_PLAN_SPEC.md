# תכנון פיננסי — אפיון למימוש

מסך דוח רווח והפסד חודשי שנבנה מכרטסת הנהלת החשבונות של הלקוח.
הפרוטוטיפ המלא: `accounting-plan.html` (מוטמע במערכת כטאב "תכנון פיננסי"),
נתוני הדוגמה: `data/ledger.js` — נוצרו מכרטסת אמיתית של 14,083 תנועות.

המסמך מכסה שלושה חלקים: **צינור הקליטה** (העלאת הכרטסת), **מודל הנתונים
והטבלאות**, ו**מפרט המסך** על שני חלקיו — הדוח וסדנת המיפוי.

---

## 1 · עקרונות שאינם ניתנים למשא ומתן

1. **כרטיס שייך לסעיף אחד בדיוק** (ולכל היותר לתת־סעיף אחד בתוכו).
   לכן סה״כ של סעיף הוא תמיד סכום הכרטיסים שבו, וסה״כ הדוח נשמר בכל
   פירוק, העברה או שינוי תצוגה. אין פיצול כרטיס באחוזים.
2. **העלאת כרטסת דורסת סכומים, לא החלטות.** הסכומים מסוכמים מחדש מהקובץ;
   ההעברות, הסעיפים שנוספו ותתי־הסעיפים נשמרים לפי מספר הכרטיס.
3. **הסיווג ההתחלתי הוא של רואה החשבון**, כפי שהוא נגזר ממבנה הכרטסת
   (טווחי מספרי כרטיסים ושמות). הוא אינו "המלצת AI" ואין להציג אותו ככזו.
   העברה שלנו גוברת עליו; ↺ מחזירה אליו — עם אזהרה.
4. **כסף לא סופרים במודל.** ה-AI ממפה מבנה ומסווג שמות; כל חיבור של
   סכומים רץ בקוד דטרמיניסטי, עם בדיקות ביקורת.
5. **PDF סרוק לא נקלט.** אין שכבת טקסט — אין קליטה. נבדק בקוד לפני
   שהקובץ מגיע למודל, ונדחה עם הודעה ברורה.

## 2 · צינור קליטת הכרטסת

### 2.1 קלט

קובץ כרטסת כפי שרו״ח מוציא אותו — Excel או PDF שהופק ממערכת הנה״ח.
אין דרישות פורמט: כל מערכת (חשבשבת, רווחית וכו׳) מוציאה עמודות אחרות,
והצינור מתמודד עם זה. דוגמה אמיתית (חשבשבת):

```
חשבון | תאור | יתרת פתיחה | תאריך למאזן | תאריך ערך | אסמכתא 1 | אסמכתא 2 |
פרטים | חשבון נגדי | תאור חשבון נגדי | מס. תנועת היומן | סוג תנועה | חובה | זכות | מט.
```

### 2.2 שלבי הצינור

```
קובץ ──► [0] ולידציה ──► [1] מיפוי מבנה (AI) ──► [2] סיכום (קוד)
              │                                        │
              ▼                                        ▼
        דחיית סריקות                        [3] בדיקות ביקורת (קוד)
                                                       │
                                                       ▼
                                   [4] סיווג כרטיסים חדשים (AI)
                                                       │
                                                       ▼
                                   [5] החלת ההחלטות הקיימות ופרסום
```

**[0] ולידציה.** Excel נכנס תמיד. PDF — בדיקת שכבת טקסט: אם אין
(`pdf.getTextContent()` ריק ברוב העמודים) הקובץ נדחה בשער:
*"הקובץ סרוק ולא ניתן לקלוט אותו במדויק — בקשו מרו״ח Excel או PDF
שהופק מהמערכת."* אין מסלול "ננסה בכל זאת".

**[1] מיפוי מבנה — קריאת מודל.** המודל מקבל את הכותרות ו-30–50 שורות
לדוגמה (לא את כל הקובץ), ומחזיר **מפה בלבד**:

```json
{
  "columns": { "account": "A", "name": "B", "date": "D",
               "debit": "M", "credit": "N" },
  "date_format": "excel_serial",
  "skip_rows": ["header", "rows_without_account",
                "opening_balance_rows", "total_rows"],
  "sign_convention": "credit_positive",
  "confidence": 0.97
}
```

`confidence < 0.9` → הקליטה נעצרת לאישור אנושי של המפה (מסך תצוגה
מקדימה: "זיהינו כך — נכון?"). ב-PDF דיגיטלי המודל גם מחלץ את השורות
עצמן, עמוד-עמוד, למבנה טבלאי — ואז ממשיכים זהה.

**[2] סיכום — קוד בלבד.** לפי המפה: קיבוץ לפי מספר כרטיס, נטו לחודש
(זכות − חובה), דילוג על שורות לפי `skip_rows`. 14,083 שורות → 631
כרטיסים. אין כאן מודל.

**[3] בדיקות ביקורת — קוד.**
- `sum(חובה) == sum(זכות)` על כל הקובץ (סטיית עיגול ≤ ‎1 ₪).
- ב-PDF: השוואת הסכום המחושב מול שורות "סה״כ" המודפסות, פר כרטיס.
- כרטיס שלא מתאזן מסומן `unverified` ולא נכנס לדוח בשקט — הוא ממתין
  לעין אנושית בסדנת המיפוי.

**[4] סיווג — קריאת מודל.** רק לכרטיסים שלא נראו מעולם (בהעלאה ראשונה:
כולם). קלט: `[{card_no, name}]`. פלט לכל כרטיס: `pl | balance`, ואם
תוצאתי — קבוצה וסעיף מוצעים + confidence. התוצאה נשמרת כ"סיווג המקור"
של הכרטיס ואינה משתנה בהעלאות הבאות.

**[5] פרסום.** הסכומים החדשים נכתבים, ההחלטות הקיימות (העברות,
תתי־סעיפים, סעיפים שנוספו) מוחלות לפי מספר כרטיס. כרטיס חדש נכנס לפי
סיווג המקור ומקבל תג "חדש" בסדנה.

### 2.3 עלויות (סדרי גודל, לחברה לחודש)

| קובץ | קריאות מודל | עלות |
|---|---|---|
| Excel | מפה (זעיר) + סיווג חדשים | < ‎0.1 ₪ |
| PDF דיגיטלי | חילוץ עמוד-עמוד + סיווג | ~‎1 ₪ |
| PDF סרוק | — נדחה — | 0 |

Batch API (עיבוד לא-מיידי) חוצה את העלות — מתאים לתהליך חודשי.

## 3 · מודל הנתונים

### 3.1 ישויות

```
Company ─┬─ LedgerUpload   (קובץ שהועלה + מפת המבנה + סטטוס)
         ├─ Card           (כרטיס הנה״ח — הזהות היא מספר הכרטיס)
         │    └─ CardMonthSum (נטו לחודש; נדרס בכל העלאה)
         ├─ Section        (סעיף בדוח — מובנה או שנוסף ידנית)
         │    └─ SubSection
         ├─ CardPlacement  (העברה שלנו; היעדרה = סיווג המקור)
         └─ Target         (יעד לחודש על סעיף/תת־סעיף/כרטיס)
```

### 3.2 טבלאות

```sql
ledger_uploads (
  id, company_id, file_name, file_type,        -- xlsx | pdf_digital
  status,        -- received|mapping|summing|auditing|classifying|ready|failed|needs_review
  period_from, period_to, rows_total,
  structure_map JSONB,                          -- הפלט של שלב [1]
  audit JSONB,                                  -- תוצאות שלב [3]
  uploaded_by, uploaded_at, error
)

cards (
  company_id, card_no,                          -- PK משותף; card_no הוא הזהות
  name,
  src_kind,        -- pl | balance              -- סיווג המקור, נקבע פעם אחת
  src_section_id,  -- NULL אם balance
  unverified BOOL, -- נכשל בביקורת בהעלאה האחרונה
  first_upload_id, last_upload_id
)

card_month_sums (
  company_id, card_no, month,                   -- YYYY-MM
  net NUMERIC,                                  -- זכות − חובה
  upload_id                                     -- נדרס בכל העלאה של אותה תקופה
)

sections (
  id, company_id, grp,                          -- rev | cogs | opex | fin
  name, color, builtin BOOL, sort
)

sub_sections ( id, section_id, name, sort )

card_placements (                               -- "MOVED" בפרוטוטיפ
  company_id, card_no,                          -- שורה קיימת = הוחלט ידנית
  section_id,                                   -- NULL = נותק, ממתין לשיוך
  sub_section_id,                               -- NULL = ישירות תחת הסעיף
  placed_by, placed_at
)

targets (
  company_id, node_kind,                        -- section | sub_section | card
  node_id, month,
  amount NUMERIC,
  is_client_goal BOOL,                          -- 🎯 נפתח למעקב אצל הלקוח
  set_by, set_at
)
```

**כלל השיוך** (ממומש בפרוטוטיפ כ-`accOf`):

```
section_of(card) = placement.section_id   אם קיימת שורת placement
                   (כולל NULL = מנותק)
                 = card.src_section_id    אחרת
```

"שונה מהמקור" = קיימת placement **וגם** היא שונה מסיווג המקור. כרטיס
שנגרר בדיוק למקום שבו הוא יושב אצל רו״ח אינו מסומן ואין לו ↺.

### 3.3 סיווג המקור — הכללים (מהכרטסת שנבדקה)

| טווח | קבוצה | חידוד לפי שם |
|---|---|---|
| 800xx | הכנסות | ריטיינר/שעות/מוקד → שירות · פרויקט → פרויקטים · אחרת → חלפים |
| 90xxx, 910xx | עלות המכר | קניות → קניות ומלאי · קבלני/ביגוד/כלי → קבלני משנה וציוד |
| 92xxx | הוצאות שכר | |
| 93xxx | תפעוליות | רכב/דלק/ליסינג → אחזקת רכב · שכירות/משרד/מחשב/חשמל → מבנה ומשרד · ייעוץ/משפט/ביטוח → שירותים מקצועיים · אחרת → הנהלה וכלליות |
| 99xxx | מימון | |
| כל השאר (1–7) | **מאזני** — לא נכנס לרו״ה | |

הטבלה הזאת היא ברירת המחדל בלבד; המודל בשלב [4] רשאי לסטות ממנה לפי
השם, וכל תוצאה ניתנת לתיקון בסדנה. בכרטסת הדוגמה: 144 תוצאתיים,
487 מאזניים — ובהם 63 כרטיסי "אחזקת רכב", אחד לכל רכב, שזה בדיוק
המקרה שתתי־הסעיפים נבנו עבורו.

## 4 · מפרט המסך — הדוח

### 4.1 מבנה

- **פס עליון:** מונה "144 כרטיסים תוצאתיים בדוח" (או "N לא שויכו" —
  כתום), שורת **רווחיות** מתקפלת (גולמי · נקי · מצטבר), בורר טווח
  חודשים + "הפקה".
- **סרגל הכרטיס:** טעינת כרטסת (עם הרמז "Excel או PDF מהמערכת ·
  סריקות לא נקלטות"), מיפוי כרטיסים, רענון, ייצוא CSV.
- **הטבלה:** עמודה לכל חודש. חודש סגור = "בפועל" מהכרטסת; החודש הרץ
  מסומן "החודש"; חודשים עתידיים = "מתוכנן".

### 4.2 היררכיית השורות

```
קבוצה (הכנסות / עלות המכר / הוצאות תפעוליות / מימון)  ← שורת סה״כ כהה
  └─ סעיף            ← תג "N כרטיסים" או "N סעיפי משנה"; שברון לפתיחה
       └─ תת־סעיף    ← אם הסעיף פורק
            └─ כרטיס  ← תג מספר הכרטיס; תג "שונה מהמקור" אם הועבר
```

שורות ביניים מחושבות: סה״כ הכנסות, סה״כ עלות המכר, **רווח גולמי**
(+% מהמחזור), סה״כ תפעוליות, ובתחתית **רווח נקי**.

### 4.3 ערך התא

| חודש | ערך | עריכה |
|---|---|---|
| סגור | סכום הכרטסת (או דריסה ידנית `BOOKS`) | כן — תיקון בפועל |
| עתידי | יעד: ידני אם הוזן, אחרת ממוצע 3 חודשים סגורים | כן — עורך התא |

עורך התא (קיים בפרוטוטיפ): יעד לחודש, השוואה לממוצע, ומתג
**"פתח יעד ללקוח 🎯"** — הכנסה = לעבור מעל, הוצאה = לא לעבור.
יעד שנקבע על הורה ואינו סכום הבנים מסומן ≠ ולא "מתוקן" בשקט.

### 4.4 פירוק סעיף לתתי־סעיפים (דיאלוג)

נפתח מריחוף על שורת סעיף. למעלה תתי־הסעיפים (שם + סכום חי + מונה),
למטה כל הכרטיסים של הסעיף, וכל כרטיס משויך בצ׳יפ. שמירה דורשת לפחות
שני תתי־סעיפים עם שם. כרטיס שלא שויך נשאר ישירות תחת הסעיף (לא נבלע).
"↺ ביטול הפירוק" מחזיר את הסעיף לשורה אחת. הסה״כ אינו משתנה לעולם.

## 5 · מפרט המסך — סדנת המיפוי

פופאפ רחב, נפתח מ"מיפוי כרטיסים". **גובה קבוע, שתי גלילות נפרדות** —
עמודת הכרטיסים ועמודת הסעיפים גוללות כל אחת בעצמה, אחרת אי אפשר לגרור
כרטיס אל סעיף שמחוץ למסך.

**עמודה ימנית — הכרטיסים:** חיפוש (שם/מספר), מסננים: הכול · ללא סעיף ·
שונו מהמקור · **מאזניים** (487 — נמצאים כאן בכוונה: אם הסיווג טעה
וכרטיס תוצאתי סווג כמאזני, מכאן מחזירים אותו). מקובץ לפי הסעיף הנוכחי;
"ללא סעיף" תמיד ראשון. כל כרטיס נגרר (drag).

**עמודה שמאלית — הסעיפים:** קבוצה בכל שורה, הסעיפים שלה ברשת. כל תיבה:
צבע, שם, מונה כרטיסים, סכום החודש הסגור האחרון, **＋ תת־סעיף**, וצ׳יפים
של הכרטיסים (עד 10 + "+N נוספים"). כל קבוצה: **＋ סעיף** (נשמר
כ-`builtin=false` — העלאת כרטסת לא נוגעת בו).

**פעולות:**
- גרירת כרטיס לתיבת סעיף / לתת־סעיף → כותב placement, טוסט, הדוח
  מתעדכן מיד.
- ✕ על צ׳יפ → ניתוק (placement עם NULL): הכרטיס עובר ל"ללא סעיף"
  ולא נספר בדוח עד שישויך.
- ↺ על כרטיס ששונה מהמקור → **פופאפ אזהרה**: הכרטיס, מאיפה→לאן,
  ומה המשמעות. אם המקור מאזני — אזהרה כתומה: "החזרה מוציאה אותו מדוח
  רווח והפסד". ההחלטה לא משתנה עד אישור; Escape סוגר את האזהרה לפני
  הסדנה.

## 8 · מקרי קצה שחובה לכסות

1. כרטיס נעלם מהכרטסת (נסגר אצל רו״ח) — נשאר בדוח עם סכומי העבר,
   לא מקבל סכומים חדשים; אין למחוק היסטוריה.
2. שני קבצים לאותה תקופה — האחרון קובע (דריסה), עם רישום מי העלה ומתי.
3. תקופה חלקית (כרטסת עד אמצע חודש) — החודש מסומן "חלקי", לא "סגור".
4. סעיף שנמחק כשיש עליו יעדים — חסימה עם הסבר, לא מחיקה שקטה.
5. כרטיס `unverified` — מוצג באדום בסדנה, לא נספר בדוח, נעלם מהסימון
   בהעלאה הבאה אם התאזן.
