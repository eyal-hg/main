# משימה — הסרגלים ורשימת הלקוחות של מנהל התזרים

# חלק א · המשימה

מסמך למתכנת ול-AI שלו. חלק א — מה לבנות עכשיו. חלק ב (נספח) — המפה המלאה של כל
הסרגלים לפי תפקיד, כדי לא לשבור סרגל של תפקיד אחר תוך כדי. הפרוטוטיפ
(`js/screens.js`: `gnavItems`, `renderGlobalRail`) הוא ההתנהגות הרצויה.

**איפה בניווט:** הסרגל הגלובלי בצד (מחוץ לחברה) בתצוגת **מנהל תזרים**; ומתחתיו רשימת
הלקוחות. בתצוגת יועץ הסרגל זהה בלי "תפעול", והרשימה בגרסת היועץ (שם + הפגישה הבאה).

## 1 · הסרגל של מנהל התזרים = הסרגל של היועץ + "תפעול"

| | היום (במערכת) | אחרי המשימה |
|---|---|---|
| פריטים | לקוחות · יומן · תקשורת · הגדרות | **תפעול · היום · משימות · יומן · תקשורת · התיק שלי** |
| דיפולט בכניסה | לקוחות | **תפעול** |
| הגדרות | בסרגל | **בתפריט המשתמש** (כמו אצל היועץ) |

- **"תפעול"** = תור הלקוחות של היום (המסך הקיים של מנהל התזרים, עם פס "מצב היום" למעלה).
- **"היום", "משימות", "יומן", "תקשורת", "התיק שלי"** — **אותם מסכים בדיוק של היועץ**. לא
  גרסה נפרדת למנהל. (במערכת היום ל"תקשורת" של המנהל יש מסך אחר — זה מתבטל.)

## 2 · רשימת הלקוחות בסרגל (מנהל תזרים)

כל שורה, מימין לשמאל:

1. **עיגול מצב תפעול** — מצב התפעול של הלקוח **היום**:

| צבע | מצב | מתי |
|---|---|---|
| אפור `#CBD7E2` | לא התחיל | אין רשומת תפעול להיום |
| צהוב `#E0A32B` | באמצע תפעול | תפעול נפתח היום ולא הסתיים (כולל "בבדיקות") |
| ירוק `#13895B` | סיים תפעול | תפעול היום הסתיים |
| אדום `#C43D30` | בעיה בנתונים | דגל `data_issue` על הלקוח — **ההגדרה המדויקת תגיע מאייל**; בפרוטוטיפ: "יתרת סוף יום לא התקבלה מהבנק" |

2. **שם החברה**, ומתחתיו **מנהל התזרים של הלקוח** (או "ללא מנהל תזרים"). זה המידע החשוב ביותר בשורה.
3. **אזהרה אדומה (משולש)** — רק ללקוח **בחריגה בפועל**: יתרת סוף היום מתחת למסגרת
   המאושרת, בחשבון אחד לפחות. לא תחזית. ב-hover: ימי חריגה, סכום, חשבון.
4. **אייקון קישור** — פותח את הלקוח ב-Bizibox בטאב חדש. לא נכנס לחברה.
5. **בלי לוגו מוצר.** המוצר לא חשוב ברשימה הזאת.

לחיצה על השורה (לא על הקישור) נכנסת לחברה.

**מקרא** קבוע מתחת לחיפוש הלקוח: ארבעת הצבעים ברשת של שתיים, ומתחתם "חריגה בפועל בבנק"
עם המשולש. בלי מקרא בתצוגת יועץ.

**הסדר:**
1. מי שלא תופעל היום — למעלה; מי שסיים — למטה.
2. בתוך כל קבוצה: מי שבחריגה בפועל — ראשון.
3. אחר כך סדר התור הרגיל (חוקי הדחיפות הקיימים).

החיפוש, הסינון לפי מנהל תזרים וסטטוס — כמו היום.

## 3 · שינויים נוספים באותו סבב

- **בורר התצוגה** ("תצוגה: יועץ / מנהל תזרים / לקוח") גלוי תמיד בפס העליון — לא מוסתר
  מאחורי דאבל-קליק על הלוגו. (רלוונטי לדמו; במערכת זה בורר הרשאות.)
- **לבעל העסק אין "שיחות טלפון"** — הפריט יורד מסרגל החברה שלו, ומהמסך העצמאי.

## 4 · API (סקיצה)

```
GET /manager/rail-clients
← [{ company_id, name, ops_manager, ops_state: 'idle'|'in_progress'|'done'|'data_issue',
     data_issue_reason?, overdraft?: {days, amount, account}, bizibox_url }]
   ממוין כבר בשרת לפי §2.
```

## 5 · קריטריונים לסיום

1. סרגל המנהל: שישה פריטים בסדר שלמעלה, "תפעול" נבחר בכניסה, אין "הגדרות" בסרגל.
2. "תקשורת" של המנהל פותח את מסך התקשורת של היועץ, פיקסל לפיקסל.
3. שורת לקוח: עיגול · שם · מנהל תזרים · (אזהרה) · קישור Bizibox; בלי מוצר.
4. הצבע משתנה במהלך היום: פתיחת תפעול → צהוב; סיום → ירוק ויורד לתחתית.
5. לקוח בחריגה בפועל מקבל משולש אדום ועולה לראש הקבוצה שלו.
6. המקרא מופיע רק בתצוגת מנהל תזרים.
7. בעל העסק לא רואה "שיחות טלפון" באף אחד משני המקומות.

# חלק ב · נספח — מפת הסרגלים לכל התפקידים

המצב כפי שהוא היום בפרוטוטיפ, אחרי המשימה שבחלק א. בסוף — הסתירות שעוד לא הוכרעו.

### העיקרון

יש **שני סרגלים**, ואף פעם לא שניהם יחד:
1. **הסרגל הגלובלי** — היעדים של בעל התפקיד, ומתחתיו רשימת הלקוחות (הדלת לחברה).
2. **סרגל החברה** — כשנכנסים לחברה הסרגל מתחלף כולו: הפס העליון נושא את שם החברה
   ואת קישור החזרה, והסרגל מסודר לקבוצות. **אותו סרגל חברה לכל התפקידים**, רק עם
   פריטים שיורדים לפי הרשאה.

### 1 · הסרגל הגלובלי

| תפקיד | פריטים (לפי הסדר) | מתחת |
|---|---|---|
| **יועץ** | היום · משימות · יומן · תקשורת · התיק שלי | חיפוש לקוח + רשימת הלקוחות (שם ופגישה הבאה) |
| **מנהל תזרים** | **תפעול** · היום · משימות · יומן · תקשורת · התיק שלי — אותו סרגל כמו היועץ, בתוספת "תפעול" (הלקוחות של היום) שהוא הראשון והדיפולט בכניסה. **המסכים זהים** ("תקשורת" = מסך התקשורת של היועץ) | רשימת הלקוחות: **עיגול מצב תפעול** (ירוק סיים · צהוב באמצע · אדום בעיה בנתונים · אפור לא התחיל) · שם · **מנהל התזרים של הלקוח** · **אזהרה אדומה** למי שבחריגה בפועל · אייקון קישור ל-Bizibox; מקרא מתחת לחיפוש. בלי מוצר. **הסדר:** מי שלא תופעל למעלה, מי שתופעל למטה; בתוך כל קבוצה חריגה בפועל ראשונה |
| **לקוח · רב-חברות** | הבית | — |
| **לקוח · חברה אחת** | אין סרגל גלובלי — הוא תמיד "בתוך החברה" | — |

"תקשורת" הגלובלי = כל הפגישות, השיחות, הקבוצות והעוזר של כל הלקוחות במסך אחד.

### 2 · סרגל החברה

| קבוצה | פריט | יועץ | מנהל תזרים | בעל העסק (באפליקציה) |
|---|---|---|---|---|
| — | חזרה (בפס העליון): "כל הלקוחות" / "חזרה" / "הבית" | ✓ | ✓ | ✓ (רב-חברות) |
| — | כפתור **תפעול** (כניסה למצב עבודה) | — | ✓ | — |
| — | דשבורד | ✓ | ✓ | ✓ |
| תקשורת | קבוצת הוואטסאפ | ✓ | ✓ | — |
| תקשורת | שיחות טלפון | ✓ | ✓ | — ("ללקוח אין שיחות טלפון") |
| תקשורת | פגישות | ✓ | ✓ | ✓ |
| ידע על החברה | זיכרון החברה | ✓ | ✓ | — |
| ידע על החברה | עוזר AI | ✓ | ✓ | ✓ |
| ידע על החברה | מדדים | ✓ | ✓ | — |
| תזרים | קליטת מסמכים | ✓ | ✓ | — |
| תזרים | מעקב ופערים | ✓ | ✓ | — |
| תזרים | תכנון חשבונאי | ✓ | ✓ | — |
| תזרים | תכנון תזרימי | ✓ | ✓ | ✓ |

| ניהול | התהליך שלי | ✓ | ✓ | — |

לא בסרגל בכוונה: **הכנה לפגישה** (מגיעים אליה מהפגישות ומהפס שעולה לפני פגישה),
**מה השתנה בתזרים** (נפתח מהדשבורד). במצב תפעול הסרגל נעול — רק "חזרה".

### 3 · איזור הניהול (Super Admin)

נפתח מתפריט המשתמש בפס העליון ("איזור הניהול"), לא מהסרגל. הסרגל שלו:
פגישות ודוחות · תפעול יומי (רק בתצוגת מנהל תזרים) · לידים · ניהול יועצים · חיוב וגבייה ·
הודעות ואוטומציה · מספרי טלפון · ניהול קטגוריות · בסיס ידע · בדיקות AI · יומן ·
**המערכת:** זיכרון לקוח — קטגוריות.

### 4 · הדפים העצמאיים של בעל העסק (`docs/cli`, white-label — הלוגו של משרד היועץ)

זהים לסרגל שלו במערכת: דשבורד · פגישות · עוזר AI · תמונת תזרים (תכנון תזרימי — במערכת בלבד).
