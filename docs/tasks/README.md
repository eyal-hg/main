**הכלל (03.09.2026):** לכל משימה תיקייה `docs/tasks/<תאריך>-<מסך>/` ובה **`TASK.md` אחד** שנכנס
כמו שהוא ל-AI של המתכנת. ב-Asana רק הכותרת, הנתיב לקובץ, ושורת הסגירה. אין תיאור, אין תגובות
עם דרישות. מה שלא בקובץ — לא קיים.

מבנה קבוע ל-`TASK.md`:
1. **איך לקרוא את הקובץ** — שורת פתיחה ל-AI: איזה מסך, איפה בניווט, שהקובץ הזה הוא המקור היחיד.
2. **א · המקור המחייב** — נתיב הפרוטוטיפ בריפו + כללי המוצר. הקובץ הרץ הוא המבנה; הפרוזה מכסה רק
   מה שהקובץ לא יכול להראות.
3. **ב · הסבב האחרון** — מה נכשל בבדיקה בסטייג׳ינג, לפי חומרה, עם מספרי הקריטריונים. מתעדכן בכל סבב.
4. **ג · מודל, הרשאות, התנהגות** — טבלאות, SQL, API, מצבים ומעברים.
5. **ד · קריטריוני מבנה** — אזור אחרי אזור מהפרוטוטיפ, עובר/נכשל. נכתבים במעבר על הקובץ, לא מבאגים.
6. **ה · איך מסיימים** — השוואה זה לצד זה, "מוכן לבדיקה" ולא Done; אנחנו בודקים בסטייג׳ינג.

תמונות — בתיקייה, לא כצרופות ב-Asana. התיקייה נדחפת ל-main ברגע שהמשימה נפתחת.
