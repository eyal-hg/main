# משימה: "משימות" — מסך המשימות של היועץ ומנהל התזרים · הנחיה ל-AI של המתכנת

> **איך לקרוא את הקובץ הזה.** אתה ה-AI שבונה את המסך **"משימות"** — הפריט השני בסרגל הגלובלי (מחוץ
> לחברה) של **היועץ** ושל **מנהל התזרים** (סרגל: [תפעול ·] היום · **משימות** · יומן · תקשורת · התיק שלי).
> מסך אחד לשני התפקידים; ההבדל: מנהל התזרים לא רואה את הטאב "ביקשתי מ-HK" (ג.1). הקובץ הזה הוא
> המקור היחיד למשימה. מה שלא כתוב כאן או לא נמצא בפרוטוטיפ — לא קיים.

## א · המקור המחייב

**`docs/adv3/tasks.html`** בריפו (main), כולל `docs/adv3/brand.css` שנטען אחריו וקובע את המראה
(Heebo, גלולות, כפתור ראשי בקורל). לפתוח בדפדפן; `?embed=1` מסתיר את הניווט הפנימי של הפרוטוטיפ
(במערכת הסרגל שלכם מחליף אותו). בנה בדיוק את מה שאתה רואה, אזור אחרי אזור, כולל הטקסטים.
צילומי המצבים בתיקייה `shots/` (ברירת מחדל · טאב HK · עורך בשורה · אישור מחיקה · סינון לפי לקוח ·
מצב ריק · משימה חוזרת בפאנל ההוספה · פופאפ הסיכום).

**כללי המוצר (חלים על כל המסך):**
- אין `<select>` נייטיב · אין `alert`/`confirm`/`prompt`. **הפרוטוטיפ משתמש ב-`<select>` בשלושה מקומות
  — עורך השורה (לקוח, תאריך יעד) ובפאנל "בקשה חדשה ל-HK" (לקוח) — זה לא לבנייה כמו שהוא:** לבנות
  באותו סגנון של **בורר הלקוח בפאנל ההוספה** (שדה חיפוש + רשימה נפתחת עם ניווט מקלדת) ושל **צ׳יפי
  "מתי"**. כל שאר הפרוטוטיפ — כן.
- פופאפ נסגר ב-✕ / Escape / רקע. מחיקה — אישור דו-שלבי **בתוך השורה** (לא פופאפ), עם "ביטול" בטוסט.
- קורל = פעולה · אדום עמוק = סכנה כספית בלבד · נייבי = מבנה · **סגול = מקור "מפגישה" בלבד** (פס בקצה
  הפנימי של השורה + שורת המקור). ערוץ אחד לכל מצב: פס = מקור · טקסט+נקודה = איחור · רקע = השורה הפתוחה.
- "HK" מותר (מסך של היועץ). לבעל העסק אין גישה למסך הזה בכלל.
- אין נתונים מומצאים; מונים מחושבים מהנתונים בזמן רינדור.

## ג · מה המסך עושה, למי, ומאיפה הנתונים

**התפקיד של המסך:** רשימת העבודה האישית של היועץ (לפי תאריך יעד, עם איחורים למעלה), הוספה מהירה
בשפה חופשית, ובנפרד — **מה שהוא ביקש ממנהל התזרים של הלקוחות שלו** ומה מצבו.

### ג.1 מי רואה מה

| תפקיד | "המשימות שלי" | "ביקשתי מ-HK" |
|---|---|---|
| `REPRESENTATIVE` · `ADMIN` (יועץ / מנהל משרד) | המשימות של המשתמש עצמו | **מוצג** — הבקשות שהוא שלח |
| `HK_REPRESENTATIVE` · `HK_CONSULTANT` · `SUPER_ADMIN` | המשימות של המשתמש עצמו | **לא מוצג** (בקשות של יועצים אליו חיות בתור התפעול שלו) |

המשימות הן **של המשתמש**, לא של המשרד: יועץ אחר באותו משרד לא רואה אותן. שיוך לחברה — מתוך
החברות שהמשתמש רואה (אותה רשימה כמו בסרגל).

### ג.2 מודל — משימה של יועץ

```sql
CREATE TABLE advisor_task (
  id             BIGSERIAL PRIMARY KEY,
  user_id        BIGINT NOT NULL,             -- הבעלים
  company_id     BIGINT,                      -- NULL = "בלי לקוח"
  text           TEXT   NOT NULL,
  note           TEXT,                        -- "הערה לעצמי"
  due_on         DATE,                        -- NULL = "בלי תאריך"
  due_time       TIME,                        -- אופציונלי: "לפני 13:00" (נגזר מהקלדה חכמה)
  done_at        TIMESTAMPTZ,
  source         TEXT   NOT NULL DEFAULT 'manual',   -- manual | meeting
  meeting_id     BIGINT,                      -- כש-source = meeting
  kind           TEXT,                        -- NULL | summary_approval | reschedule (משימות עם פעולה)
  recur_mode     TEXT,                        -- NULL | weekly | monthly
  recur_days     INT[],                       -- weekly: 0..5 (א׳..ו׳)
  recur_day      INT,                         -- monthly: 1..28
  series_id      BIGINT,                      -- כל המופעים של משימה חוזרת חולקים series_id
  sent_to_client_at TIMESTAMPTZ,              -- "נשלח ללקוח"
  sort_order     INT,                         -- סדר ידני בתוך היום (גרירה במסך "היום")
  created_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

**כללים:**
- **קבוצות** (לפי `due_on`): **עבר זמנן** (`due_on < היום` ולא בוצעה) · **היום** · כל תאריך עתידי
  בקבוצה משלו ("03.07 · מחר · שישי", "08.07 · רביעי") · **בלי תאריך** אחרון. משימה שבוצעה נשארת
  בקבוצה שלה (מחוקה), לא עוברת ל"עבר זמנן".
- **משימות מפגישה** (`source = meeting`): נוצרות אוטומטית מסיכום הפגישה (המשימות ש"נולדו מהפגישה"
  ליועץ) ומאירועי פגישה: פגישה שהוקלטה והסיכום מוכן → משימה `kind = summary_approval` "אישור סיכום —
  {שם הפגישה}" להיום; פגישה שלא התקיימה → `kind = reschedule` "תיאום מחדש — הפגישה לא התקיימה" להיום.
  שורת המקור מקשרת לפגישה במסך התקשורת.
- **משימה חוזרת:** סימון "בוצע" על מופע יוצר את המופע הבא (שבועי: היום הבא מבין `recur_days`;
  חודשי: `recur_day` בחודש הבא, או בחודש הזה אם עוד לא עבר). מחיקה: "רק המופע הזה" (יוצר את הבא) או
  "כל הסדרה" (`series_id`). טקסט התצוגה: "כל יום חמישי" / "כל שבוע — שני, חמישי" / "כל 1 בחודש".
- **שליחה ללקוח בוואטסאפ** (רק כשיש חברה): שולחת את טקסט המשימה לאיש הקשר הראשי של החברה דרך
  מנגנון ההודעות הקיים (תבנית מאושרת — אותה תבנית של משימה מהתפעול), **ומציגה את המשימה ללקוח
  בדשבורד שלו** בכרטיס המשימות שמחכות ממנו (הכרטיס "משימות מנהל התזרים" בדשבורד בעל העסק). פעולה
  בלתי הפיכה → שני שלבים: לחיצה ראשונה מחליפה את הכפתור ל"לשלוח ל{לקוח}? לחיצה נוספת שולחת".
- **"הבאה בתור"** (בפס): המשימה הפתוחה הראשונה מהיום, ואם אין — הראשונה ברשימה (כולל איחורים);
  כשיש סינון — מתוך המסונן.
- **הקלדה חכמה** בשדה ההוספה, תוך כדי הקלדה: `@טקסט` מזהה לקוח (התאמה חלקית לשם, כמו בסרגל) ובוחר
  אותו; המילים **מחר / בשבוע / היום** קובעות את "מתי" (ומוסרות מהטקסט בשמירה); `hh:mm` הופך
  ל"לפני hh:mm"; שורת התצוגה המקדימה מציגה: → {לקוח} · {תאריך} · {לפני שעה} · {↻ חזרה} · {→ ללקוח}.

### ג.3 מודל — בקשה ממנהל התזרים ("ביקשתי מ-HK")

**אותה ישות** של "בקשה חדשה למנהל התזרים" שבעל העסק שולח מהדשבורד שלו (`docs/CLIENT_SCREENS_SPEC.md`
§ "בקשה חדשה למנהל התזרים": אירוע בתור הודעות הלקוח) — כאן השולח הוא היועץ. שדות שהמסך צריך:
טקסט הבקשה · חברה · מנהל התזרים של החברה (נגזר) · `due_on` (יעד; "—" אם לא נקבע) · מצב:
**פתוח** (אפור) · **ממתין לחומר** (ענבר — מנהל התזרים סימן שהוא מחכה לחומר מהלקוח; תת-שורה "חומר
אחרון שהתקבל — {תאריך}") · **נסגר · {תאריך}** (ירוק — האירוע טופל). "נסגרו השבוע" = נסגרו ב-7 הימים
האחרונים. אין מצבים אחרים.

### ג.4 חוזה URL

`?c=<company_id>` מסנן לפי לקוח (הפאנל "לפי לקוח" מסומן, ובפאנל ההוספה הלקוח כבר נבחר) · `?q=`
חיפוש · `?f=open|done` מצב · `#hk` פותח את טאב HK. מ"התיק שלי" → "+ משימה לחברה" מגיע עם `?c=`.

    מצב (מיושר לשמאל): "● פתוח" (אפור) · "● ממתין לחומר" (ענבר) · "● נסגר · 01.07" (ירוק). מיון: פתוחות
    לפי יעד, אחריהן הסגורות.
12. שורת תחתית קבועה: "{n} פתוחות אצל מנהלי התזרים · {m} נסגרו השבוע · הכי ותיקה: {טקסט הבקשה
    הפתוחה הוותיקה ביותר}". מצב ריק: "אין בקשות במצב הזה" · "הבקשות קיימות — רק לא במצב שנבחר." ·
    "הצגת כל הבקשות".

**ה · העמודה הצדדית בטאב שלי (470px; 430 ב-≤1450)**
13. פאנל **"משימה חדשה"** — הבלוק הנייבי היחיד בגוף: כותרת נייבי "משימה חדשה · Enter מוסיף". גוף: שדה
    גדול "מה צריך לעשות?" (17px, מודגש, קו תחתון מקווקו בפוקוס) · **שורת תצוגה מקדימה** של ההקלדה
    החכמה (ג.2) — ריקה: "אפשר להקליד @לקוח, "מחר", "בשבוע"" · **לקוח**: שדה "חיפוש לקוח…" עם רשימה
    נפתחת (שם + מנהל התזרים, חצים/Enter/Escape, "לא נמצא"); לקוח נבחר → צ׳יפ תכלת עם ✕ · **מתי**:
    צ׳יפים היום (ברירת מחדל) / מחר / בשבוע / בלי / 📅 תאריך (פותח בורר תאריך; התאריך שנבחר מחליף את
    תווית הצ׳יפ) · **חוזרת**: לא / כל שבוע / כל חודש; שבועי → צ׳יפי א׳–ו׳ (ברירת מחדל ה׳, אפשר כמה,
    לא ניתן לבטל את האחרון); חודשי → גריד 1–28; ומתחת סיכום "כל יום חמישי" · **מתג "לשלוח ללקוח
    בוואטסאפ"** — כשדולק מופיע "הלקוח יראה אותה אצלו ב'מה מחכה ממני'"; דולק בלי לקוח → טוסט "כדי
    לשלוח ללקוח צריך לבחור לקוח" והפוקוס לבורר · **"הערה לעצמי…"** · כפתור **"הוספה"** (ראשי, קורל).
    אחרי הוספה: השורה נכנסת לקבוצה הנכונה, טוסט "נוסף: {טקסט}[ · נשלח ללקוח בוואטסאפ]", הטופס
    מתאפס והפוקוס חוזר לשדה.
14. פאנל **"לפי לקוח"** ("לחיצה מסננת · נקודה = יש איחור"): "כל הלקוחות [N]" · שורה לכל חברה עם
    משימות · "בלי לקוח [N]". המונה = פתוחות בלבד (0 מעומעם); **נקודת קורל** לפני שם לקוח שיש לו
    משימה באיחור. הנבחר = נייבי. הלחיצה מסננת את הרשימה ומעדכנת את "ניקוי הסינון".

**ו · העמודה הצדדית בטאב HK**
15. פאנל נייבי **"בקשה חדשה ל-HK · Enter שולח"**: שדה "מה לבקש ממנהל התזרים?" · **לקוח** (בורר עם
    חיפוש — לא `<select>`) · "**שליחה ל-HK**" (ראשי). חסר טקסט או לקוח → טוסט "מה לבקש ולאיזה לקוח"
    והפוקוס לשדה החסר. אחרי שליחה: שורה חדשה בראש הטבלה במצב "נשלח עכשיו", טוסט "נשלח ל{מנהל
    התזרים של הלקוח}".
16. פאנל **"נסגרו השבוע · N בקשות"**: רשימה — טקסט הבקשה (מודגש) ומתחתיו "{לקוח} · {מנהל תזרים} ·
    נסגר {תאריך}".

**ז · פופאפ אישור הסיכום** (מ"אישור הסיכום" בשורה)
17. כותרת "סיכום — {שם הפגישה}" · תת-כותרת "{לקוח} · {תאריך שעה} · עם {משתתף} · הוקלטה N דק׳" ·
    רשימה ממוספרת של סעיפי הסיכום · כפתורים: **"אישור ושליחה ללקוח"** (ראשי) · "אישור בלי שליחה" ·
    "לעריכה במסך הפגישות" (פותח את הפגישה במסך התקשורת). אישור → טוסט "הסיכום אושר [ונשלח
    ל{משתתף}]", המשימה מסומנת כבוצעה והפעולה בשורה מתחלפת ל"הסיכום אושר". ✕/Escape/רקע סוגרים.
    אותו פופאפ בדיוק כמו במסך "היום".

**ח · כללי**
18. אין `<select>` נייטיב בשום מקום; כל הבוררים בסגנון בורר הלקוח. Escape סוגר עורך/רשימה/פופאפ.
19. הגובה: העמודה הצדדית נמתחת עם הרשימה (אין sticky עם גובה קבוע); הרשימה גוללת בדף. אין גלילה
    אופקית.
20. כל שינוי (הוספה, סימון, עריכה, מחיקה, שליחה) נשמר בשרת מיד; רענון הדף מחזיר את אותו מצב כולל
    הטאב ו-`?c=`.
