## א · המקור המחייב

**`docs/adv3/clients.html`** בריפו (main), כולל `docs/adv3/brand.css` שנטען אחריו וקובע את המראה
(Heebo, גלולות, כפתור ראשי בקורל, פאנלים ברדיוס 14). לפתוח בדפדפן (`?embed=1` מסתיר את הניווט
הפנימי של הפרוטוטיפ — במערכת הסרגל שלכם מחליף אותו). בנה בדיוק את מה שאתה רואה, אזור אחרי אזור,
כולל הטקסטים. הקובץ הרץ הוא המבנה; המלל כאן מכסה רק מה שהקובץ לא יכול להראות (נתונים, הרשאות,
מקורות). צילומי המצבים ב-`shots/`: ברירת מחדל · סינון לפי סטטוס · סינון מהפס (בעיה תזרימית) · מצב
ריק · תפריט הסטטוס בשורה · פופאפ הגדרת הסטטוסים · טאב "פגישות" בכרטיס · חלון 1200.

**כללי המוצר (חלים על כל המסך):**
- אין `<select>` נייטיב · אין `alert`/`confirm`/`prompt`. **הפרוטוטיפ עצמו משתמש ב-`<select>` בבורר
  הסדר ("סדר · יעד לסטטוס") — זה לא לבנייה כמו שהוא:** לבנות תפריט מותאם באותו סגנון של תפריט
  הסטטוס בשורה (`.stmenu`). כל שאר הפרוטוטיפ — כן.
- פופאפ נסגר ב-✕ / Escape / לחיצה על הרקע. פופאפ נופל במרכז החלק הנראה של המסך.
- קורל = פעולה · אדום עמוק `#C43D30` = סכנה כספית בלבד · נייבי = מבנה (פס עליון, ראש הכרטיס,
  צ׳יפ פעיל) · אין סגול חדש (הסגול היחיד הוא צבע הסטטוס "יעדים עודכנו" שהמשרד הגדיר).

- "HK" מותר כאן (זה מסך של היועץ, לא של בעל העסק).
- מספרים ותאריכים בספרות לטיניות, `dd.mm`; "היום 17:00" כשזה היום.
- אין נתונים מומצאים: שדה שאין לו מקור מוצג כ-"—" (או לא מוצג), לא כמספר.

## ג · מה המסך עושה, למי, ומאיפה הנתונים

**התפקיד של המסך:** תמונת הניהול של התיק — לכל לקוח **סטטוס בתהליך החודשי**, **יעד לסטטוס הבא**,
הפגישה האחרונה והבאה, וההתראות. זה לא "רשימת לקוחות" (הרשימה היא בסרגל) — זה מסך עבודה.

### ג.1 מי רואה מה

| תפקיד | אילו חברות בטבלה | "הגדרת סטטוסים" |
|---|---|---|
| `REPRESENTATIVE` (יועץ) | החברות שהוא היועץ שלהן | לא מוצג |
| `ADMIN` (מנהל חברת ייעוץ) | כל החברות של המשרד | **מוצג** — עורך את הסטטוסים של המשרד |
| `HK_REPRESENTATIVE` · `HK_CONSULTANT` | כפי שהיום (ההרשאות הקיימות) | לא מוצג |
| `SUPER_ADMIN` | כל החברות | **מוצג** — עורך את הסטטוסים של HK |

הסטטוסים מוגדרים **ברמת העסק (business) של המשתמש** — משרד ייעוץ אחד = סט סטטוסים אחד לכל
היועצים בו; HK = סט משלו. תמיד **סטטוס אחד לכל לקוח**.

### ג.2 מודל

```sql
-- הגדרת הסטטוסים של המשרד (סדר = שלבי התהליך)
CREATE TABLE client_status_def (
  id            BIGSERIAL PRIMARY KEY,
  business_id   BIGINT NOT NULL,          -- המשרד / HK
  name          TEXT   NOT NULL,          -- "ממתין לחומר"
  color         TEXT   NOT NULL,          -- hex מתוך הפלטה של 8 הצבעים בפרוטוטיפ
  sort_order    INT    NOT NULL,          -- 1..n
  default_days  INT    NOT NULL DEFAULT 5,-- ברירת המחדל ל"יעד לסטטוס הבא"
  deleted_at    TIMESTAMPTZ
);
-- המצב של כל חברה
CREATE TABLE company_status (
  company_id    BIGINT PRIMARY KEY,
  status_id     BIGINT NOT NULL REFERENCES client_status_def(id),
  due_on        DATE,                     -- יעד לסטטוס הבא; NULL בסטטוס האחרון
  set_by        BIGINT NOT NULL,          -- user
  set_at        TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

**ברירת מחדל בהקמה:** חמשת הסטטוסים של הפרוטוטיפ, בסדר ובצבעים שלו: ממתין לחומר `#C4CED8` ·
הוזן `#39ABE2` · יעדים עודכנו `#6B4FA0` · מוכן לפגישה `#13895b` · סיכום אושר `#0C4068`, כולם 5 ימים.
חברה חדשה נכנסת לסטטוס הראשון עם `due_on = היום + default_days`.

**כללי הסטטוס:**
- החלפת סטטוס (מהשורה או מהכרטיס) → `due_on = היום + default_days` של הסטטוס החדש. היועץ יכול
  לדרוס את התאריך (עריכה בשורה או בכרטיס, `dd.mm`).
- הסטטוס האחרון בסדר = סוף התהליך: בלי יעד, בלי "עבר את היעד".
- **באיחור** = `due_on < היום` והסטטוס אינו האחרון. מוצג באדום. מונה "עברו יעד לסטטוס" נגזר מזה.
- עריכת ההגדרות: שינוי סדר → החברות נשארות בסטטוס שלהן (מיפוי לפי id, לא לפי מיקום). מחיקה
  מותרת רק לסטטוס שאין בו חברות (הכפתור מנוטרל עם טולטיפ "יש לקוחות בסטטוס הזה — קודם להעביר
  אותם"). שמירה בלי שם → הודעה "לכל סטטוס צריך שם", לא נשמר.

### ג.3 מקורות לשאר העמודות (לא להמציא)

| עמודה / שדה | מקור |
|---|---|
| חברה · ח.פ · חבילה (Money / Money+ / Meeting) · מנהל התזרים | טבלת החברה כפי שהיום |
| פגישה אחרונה | הפגישה האחרונה **שהתקיימה או תוכננה ועבר מועדה** במסך הפגישות של החברה. תת-שורה: "לפני N ימים"; אם לא התקיימה — "לא התקיימה"; אם אין — "טרם נפגשתם" |
| פגישה הבאה | הפגישה העתידית הקרובה של החברה — **אותו מקור** כמו "הפגישה הבאה" בדשבורד של בעל העסק ובציר הפגישות. אין → "לא נקבעה" + "שליחת לינק" |
| "שליחת לינק" | שולח ללקוח בוואטסאפ את לינק קביעת הפגישה הקיים במערכת (אותו לינק שבמסך הפגישות). טוסט "לינק לקביעת פגישה נשלח — {חברה}" |
| התראה "בעיה תזרימית" (אדום) | **חריגה בפועל**: יתרת סוף היום מתחת למסגרת המאושרת בחשבון אחד לפחות — אותה הגדרה כמו האזהרה האדומה ברשימת הלקוחות (`docs/tasks/2026-09-02-rails/TASK_RAILS.md` §2). לא תחזית |
| התראה "אי שביעות רצון" (ענבר) | הרשומה האחרונה בזיכרון החברה בקטגוריה "שביעות רצון" מסומנת כירידה, ב-30 הימים האחרונים. אין קטגוריה כזאת בזיכרון → ההתראה לא קיימת במסך (לא להמציא) |
| כרטיס — "לקוח מאז" | חודש ושנת פתיחת החברה (`mm.yyyy`) |
| כרטיס — "אנשים" | אנשי הקשר של החברה: שם + תפקיד, ו-"· בקבוצה" אם הוא בקבוצת הוואטסאפ |
| כרטיס — "משימות פתוחות" | המשימות הפתוחות של היועץ עם שיוך לחברה הזאת (מסך "משימות") |
| כרטיס — טאב "פגישות" | ציר הפגישות של החברה (תאריך · שם · מצב) |
| כרטיס — טאב "זיכרון" | הרשומות האחרונות בזיכרון החברה (קטגוריה · טקסט · מתי) |
| הפס — "N לקוחות עם בעיה תזרימית" / "לקוח אחד באי שביעות רצון" | ספירה מהטבלה **המלאה** (לא מהמסוננת) |

### ג.4 חוזה URL

`?c=<company_id>` פותח את הכרטיס של החברה · `?q=` ממלא את החיפוש · `?f=<שם סטטוס | cf | sat | nom | lt>`
מפעיל מסנן (סטטוס / בעיה תזרימית / אי שביעות רצון / בלי פגישה הבאה / עברו יעד). קישור ישיר
טוען את המסך עם המסנן והכרטיס — לא מסך ריק.

## ד · קריטריוני מבנה — אזור אחרי אזור (עובר / נכשל)

**א · הפס העליון (נייבי, 68px)**
1. מימין: **"התיק שלי"** (כותרת עם קו תחתון קורל) · "יום חמישי · 02.07.2026" · מפריד אנכי. משמאל: השעה.
2. באמצע — **משפט ההתראות**, לא מונים: "**4** לקוחות עם **בעיה תזרימית**" (המילים באדום) ·
   "לקוח אחד **באי שביעות רצון**" (ענבר). רק המילים הצבועות לחיצות; לחיצה מסננת את הטבלה
   (ומודגשת כפעילה), לחיצה שנייה מבטלת. 0 לקוחות → המשפט לא מוצג. יחיד = "לקוח אחד", רבים = מספר.

**ב · ראש הפאנל**
3. "**התיק שלי**" · רמז: "22 חברות"; כשיש סינון — "**{המסננים · מופרדים בנקודה}** · N מתוך 22".
4. כלים משמאל: **בורר סדר** (תפריט מותאם, לא נייטיב) עם "סדר · יעד לסטטוס" (ברירת מחדל) · "סדר ·
   פגישה אחרונה" · "סדר · פגישה הבאה" · "סדר · שם החברה" · **חיפוש** "חיפוש חברה או ח.פ" (מסנן
   תוך כדי הקלדה, על שם או ח.פ) · צ׳יפ **"הגדרת סטטוסים"** — רק ל-ADMIN / SUPER_ADMIN (ג.1).

**ג · שורת הסינון**
5. תווית "סטטוס" ואחריה **צ׳יפ לכל סטטוס** של המשרד, בסדר ההגדרה: נקודת צבע · שם · מונה. המונה =
   כמה חברות היו בסטטוס הזה **בהינתן שאר המסננים** (חיפוש/התראה). צ׳יפ פעיל = מילוי נייבי.
   לחיצה שנייה מבטלת. סטטוס עם 0 עדיין מוצג (זה שלב בתהליך, לא סינון מקרי).
6. "ניקוי המסננים" מופיע רק כשיש מסנן כלשהו (סטטוס / התראה / חיפוש), ומאפס הכל.

**ד · הטבלה (6 עמודות — לא יותר)**
7. עמודות: **חברה · סטטוס · יעד · פגישה אחרונה · פגישה הבאה · התראות**. שורה 44px. עמודת חברה:
   שם (מודגש) ומתחתיו ח.פ קטן, ו-**↗** שפותח את דשבורד החברה בטאב חדש (לא נכנס לכרטיס).
8. **סטטוס**: טוקן (נקודת צבע + שם + חץ קטן). לחיצה פותחת **תפריט בשורה** עם כל הסטטוסים כצ׳יפים,
   הנוכחי מסומן; בחירה מחליפה, מעדכנת את היעד (ג.2) ואת הכרטיס אם הוא פתוח, ומציגה טוסט
   "{חברה} — {סטטוס}". התפריט נסגר בלחיצה בחוץ / Escape / גלילה. אותו טוקן בדיוק ב-3 המקומות:
   צ׳יפ הסינון, תא הטבלה, עורך הסטטוס בכרטיס.
9. **יעד**: `dd.mm`; **אדום** כשעבר (בלי המילים "עבר"/"עד" — הצבע אומר); ריק בסטטוס האחרון.
   לחיצה → שדה בשורה (`dd.mm`, Enter שומר, Escape מבטל, blur שומר). ערך לא תקין — לא נשמר.
10. **פגישה אחרונה**: תאריך ומתחתיו "לפני N ימים" / "לא התקיימה" / "ממתין לחומר מ-25.06"; אין →
    "טרם נפגשתם" (אפור). **פגישה הבאה**: "היום 17:00" מודגש נייבי / "05.07 16:00"; אין → "**לא
    נקבעה**" (אדום) ומתחתיו קישור "**שליחת לינק**" (תכלת) — הקישור לא פותח את הכרטיס.
11. **התראות**: "● בעיה תזרימית" (אדום) ו/או "● אי שביעות רצון" (ענבר), אחת מתחת לשנייה; טקסט +
    נקודה, **בלי רקע**. ריק כשאין.
12. **לחיצה על שורה** (וגם Enter/רווח כשהיא בפוקוס) פותחת את הכרטיס ומסמנת את השורה (רקע תכלת
    בהיר). הסימון מגיע מהפונקציה שפותחת את הכרטיס — לא מה-click handler — כך שגם `?c=` מסמן.
13. **סינון**: שורות שלא תואמות **מעומעמות ויורדות לתחתית** עם קו הפרדה מעל הראשונה שבהן — לא
    נעלמות (היועץ רואה את כל התיק בכל מצב). 0 תוצאות → הטבלה מוסתרת ובמקומה **מצב ריק**: "אין
    חברה שתואמת את הסינון" · שורה שמסבירה (החיפוש / צירוף המסננים) · כפתור "ניקוי כל המסננים".
14. **סדר ברירת מחדל**: לפי יעד לסטטוס — הקרוב/שעבר למעלה, "היום" לפני תאריכים, בלי יעד למטה;
    שוויון → לפי שם. סדר לפי "פגישה הבאה": "היום" קודם, "לא נקבעה" אחרון.

**ה · הכרטיס (עמודה שמאלית, 430px; ב-≤1450 — 300px; לא sticky עם גובה קבוע)**
15. **הכרטיס אף פעם לא ריק**: בכניסה נפתח הראשון בסדר התצוגה, או `?c=`.
16. ראש נייבי: שם החברה (גדול) · "{ח.פ} ח.פ · {חבילה} · {מנהל התזרים}" · **עורך הסטטוס**: כל
    הסטטוסים כצ׳יפים (נקודת צבע + שם), הנוכחי מלא. מתחתיו שורת היעד: "יעד לסטטוס הבא" (או
    "**עבר את היעד**" באדום, עם מסגרת אדומה לשדה) · שדה `dd.mm` · "ברירת מחדל · N ימים" (טולטיפ:
    "ברירת המחדל נקבעת בהגדרות המשרד"). לא מוצגת בסטטוס האחרון.
17. טאבים: **סקירה · משימות N · פגישות N · זיכרון N** (המונים מהנתונים). הטאב הנבחר נשמר בין
    חברות (מעבר לחברה אחרת לא מקפיץ ל"סקירה").
18. **סקירה** — שורות מפתח/ערך: לקוח מאז · אנשים (שם מודגש + תפקיד, שורה לאיש) · פגישה אחרונה
    (תאריך + "לפני N ימים" + תת-שורה אם לא התקיימה) · פגישה הבאה (או "לא נקבעה" + "שליחת לינק") ·
    התראות (או "אין") · משימות פתוחות (תיבות סימון — סימון מסמן כבוצע במסך המשימות, טוסט; או
    "אין משימות פתוחות").
19. **משימות**: אותה רשימה עם תיבות סימון + "**+ משימה לחברה**" → מסך המשימות עם `?c=` (הלקוח
    כבר נבחר בפאנל ההוספה). **פגישות**: שורה לפגישה — תאריך·שעה · שם · מצב ("הוקלטה · סיכום
    לאישור" / "סיכום נשלח ✓" / "לא התקיימה" / "היום · ההכנה נפתחה"); ריק → "אין פגישות".
    **זיכרון**: קטגוריה · טקסט · מתי; ריק → "עוד לא נלמד כלום".
20. תחתית הכרטיס (תמיד גלויה, לא מתחת לקפל): "**הדשבורד של החברה ↗**" (ראשי, קורל בפרוטוטיפ —
    פותח את החברה) · "הזיכרון המלא" (זיכרון החברה) · "כל הפגישות" (פגישות החברה).

**ו · פופאפ "הגדרת סטטוסים" (ADMIN / SUPER_ADMIN בלבד)**
21. כותרת "הגדרת סטטוסים" · תת-כותרת "מוגדר לכל המשרד על ידי יועץ אדמין · תמיד סטטוס אחד לכל
    לקוח" · ✕. שורה לסטטוס: מספר סידורי · **נקודת צבע** (לחיצה פותחת פלטה של 8 צבעים — אלה שבקובץ)
    · שדה שם · "יעד [N] ימים" · "N לקוחות" (כמה בסטטוס) · ↑ ↓ (הראשון/האחרון מנוטרלים) · ✕ מחיקה
    (מנוטרל כשיש לקוחות, עם הטולטיפ מ-ג.2).
22. "+ סטטוס חדש" מוסיף שורה ("סטטוס חדש", הצבע הבא בפלטה, 5 ימים). הערה בתחתית: "היעד קובע את
    ברירת המחדל של 'יעד לסטטוס הבא' — היועץ יכול לדרוס פר לקוח." כפתורים: **שמירה** (ראשי) ·
    ביטול. שמירה → הטבלה, הצ׳יפים והכרטיס מתעדכנים מיד; טוסט "הסטטוסים עודכנו — לכל המשרד".
    Escape / רקע / ✕ = ביטול בלי שמירה.

**ז · כללי**
23. המסך **נעול לגובה החלון**: הטבלה גוללת בתוך הפאנל (כותרות העמודות דביקות למעלה), הכרטיס לא
    יורד מתחת לקפל (הטאב הפעיל גולל בפנים, תחתית הכרטיס תמיד גלויה), אין גלילה של הדף כולו. הפופאפ
    נופל במרכז החלק הנראה.
23א. **רוחבים** (לפי הקובץ): ≤1450 — הכרטיס 430px, התאים נשברים לשתי שורות ("לפני N ימים" יורד מתחת
    לתאריך), ח.פ מוסתר; ≤1200 — הכרטיס 360px; ≤1080 — הכרטיס 300px, "לפני N ימים" יורד מהטבלה (נשאר
    בכרטיס), ועמודת "חברה" נעוצה כשהטבלה נגללת לרוחב. **אף עמודה לא מוסתרת** בשום רוחב.
23ב. **hover**: שורת טבלה — רקע בהיר; ↗ ליד שם החברה מופיע רק ב-hover; שדה היעד — מסגרת תכלת; צ׳יפ —
    כהה מעט. מקלדת: שורה בפוקוס נפתחת ב-Enter/רווח; טבעת פוקוס תכלת (`:focus-visible`).
24. אין `<select>` נייטיב (גם לא בבורר הסדר); כל תפריט נסגר ב-Escape / בחוץ; טוסט לכל שינוי
    (סטטוס, יעד, שליחת לינק, סימון משימה).
25. כל שינוי סטטוס/יעד נשמר בשרת מיד (בלי כפתור "שמור") ומופיע אצל יועץ אחר של אותו משרד ברענון.

"הגדרת סטטוסים") וכמנהל תזרים — ועוברים על 1–25. לא Done — תגובה **"מוכן לבדיקה"**; אנחנו בודקים
