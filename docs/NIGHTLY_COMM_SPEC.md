# הג׳וב הלילי וג׳וב הבוקר — סיכום

**העיקרון:** יש טבלת `Meeting` ותהליך אסינכרוני שלוקח את התמלול של רשומה
ומוציא ממנו סיכום, משימות, משוב וזיכרון לקוח. שיחות הטלפון כבר נכנסות
לאותו תהליך. **קבוצות הוואטסאפ וההתכתבות עם העוזר נכנסות אליו גם כן.**

אין צינור חדש. הג׳וב הלילי רק **מזין** רשומות; ג׳וב הבוקר רק כותב את
תקציר הבוקר.

# חלק א · הג׳וב הלילי

## מה הג׳וב עושה

בלילה, לכל חברה:

1. **לכל קבוצת וואטסאפ שהייתה פעילה היום** — יוצר רשומת `Meeting` אחת,
   `kind = wa`, שה"תמלול" שלה הוא הודעות היום.
2. **לכל יוזר שהתכתב היום עם העוזר בוואטסאפ** — יוצר רשומת `Meeting` אחת,
   `kind = ai`, שה"תמלול" שלה הוא ההתכתבות של אותו יוזר.
3. **מטמיע (embeddings)** את סיכומי היום לחיפוש, ומריץ מחדש עיבודים שנפלו
   במהלך היום.

מכאן התהליך הקיים עושה את מה שהוא עושה לפגישה ולשיחה. הזיכרון מתעדכן
דרכו — לא בשלב נפרד.

## 1 · הרשומה שהג׳וב יוצר

| שדה | קבוצה (`wa`) | עוזר (`ai`) |
|---|---|---|
| `kind` | `wa` | `ai` |
| `company_id` | החברה של הקבוצה | החברה של היוזר |
| `source_id` | מזהה הקבוצה | מזהה היוזר |
| `day` | היום המסוכם | היום המסוכם |
| `transcript` | הודעות היום, בפורמט שלמטה | ההתכתבות של היום |
| `participants` | הכותבים המזוהים | היוזר |
| מפתח ייחודי | `(kind, source_id, day)` | `(kind, source_id, day)` |

- **ריצה חוזרת מחליפה, לא מכפילה** — המפתח הייחודי הוא האידמפוטנטיות.
- **יום בלי פעילות — אין רשומה.** לא יוצרים "סיכום ריק".
- **הודעה אחרי חצות** שייכת ליום החדש; הלילה הבא יתפוס אותה.

**פורמט התמלול** — שורה להודעה, כמו תמלול עם דוברים:

```
[10:12] צחי עובד: העברתי את שני השיקים של הספקים
[10:40] מיכל: תודה, נכנס לתפעול
[12:58] 054-771-2280 (לא מזוהה): מתי הכסף נכנס?
```

מספר לא מזוהה נכנס עם הסימון — כדי שהזיכרון האישי לא ייחס לו כלום. אין
ניחוש זהות.

## 2 · מסכת תוצרים לפי kind

התהליך מייצר ארבעה תוצרים. לא כל `kind` מקבל את כולם — עמודה אחת
ב-`Meeting` ותנאי אחד בתהליך:

| `kind` | סיכום | משימות | משוב ליועץ | זיכרון |
|---|---|---|---|---|
| `meet` פגישה | ✓ | ✓ | ✓ | ✓ |
| `call` שיחה | ✓ | ✓ | כפי שהיום | ✓ |
| `wa` קבוצה | ✓ | — | — | ✓ |
| `ai` עוזר | ✓ | ✓ | — | ✓ |

- **קבוצה בלי משימות:** הן כבר תויגו בזמן אמת על ההודעות
  (`משימת הזנה` · `נגררת` · `בקשה פתוחה` · `טבלת הזנה`). חילוץ נוסף בלילה
  יכפיל אותן.
- **קבוצה ועוזר בלי משוב:** המשוב הוא על ניהול פגישה. אין פגישה.
- **עוזר עם משימות:** שאלה של היוזר שדורשת יועץ ("מה זאת אומרת חריגה?")
  הופכת למשימה מוצעת, כמו היום.
- **זיכרון "אין עדכון" הוא תוצאה מפורשת** — בקבוצה מוצג
  *"לא נמצא מה להוסיף לזיכרון"*. שקט הוא מידע.

## 3 · מה לא משתנה

- **התהליך עצמו** — אותם פרומפטים, אותם קטגוריות זיכרון (`MEM_CATS`),
  אותה הפרדת scope חברה / אישי.
- **הצגה אחת, רשומה אחת** — הסיכום שמופיע בתוך הקבוצה בין יום ליום ובמסך
  התקשורת כשורת `wa` הוא **אותה רשומת `Meeting`**. כתיבה אחת.
- **שיחה לא משויכת לא מעובדת** — נשארת בתור הלא־מזוהות עד שיוך; השיוך
  מפעיל את התהליך מיד, לא מחכה ללילה.
- **הצ׳אט שבתוך האפליקציה** אינו תקשורת ואינו מסוכם. רק ערוץ הוואטסאפ מול
  העוזר.

## 4 · מה עוד רץ בלילה

- **embeddings** — כל סיכום של היום (מכל ה-`kind`) נחתך לסעיפים ומוטמע
  לחיפוש הסמנטי. סיכומים ושורות זיכרון — לא תמלולים גולמיים.
- **השלמות** — רשומת `Meeting` בלי סיכום אחרי X שעות מריצים שוב. רשת
  ביטחון, לא המסלול הראשי.
- **מונים** — ספירת הלא־מזוהות לרצועת "ממתין לשיוך".
- **תצפית** — ריצה נרשמת (חברה, יום, התחלה, סיום, ok, שגיאה) ועולה לדוח
  התפעול היומי. כשל בקבוצה אחת לא מפיל את השאר.

```
02:00, פר חברה
──► [1] לכל קבוצה פעילה: Meeting(kind=wa, day)        (קוד)
──► [2] לכל יוזר פעיל מול העוזר: Meeting(kind=ai, day) (קוד)
──► [3] התהליך האסינכרוני הקיים מעבד את הרשומות       (כמו פגישה ושיחה)
──► [4] embeddings לסיכומי היום · השלמות · מונים
```

## 5 · פתוח להכרעה

- **משתתפים בקבוצה** — בפגישה משייכים עד שניים לזיכרון האישי; בקבוצה
  הכותבים הם חמישה־שישה. לבדוק שהתהליך מקבל N משתתפים, או שהזיכרון האישי
  מקבוצה נכתב רק לכותבים מזוהים.
- **משוב על שיחת טלפון** — היום נוצר כי התהליך מייצר הכל. אם אין לו ערך
  בשיחה, זו אותה עמודת מסכה.

# חלק ב · ג׳וב הבוקר

## מה הג׳וב עושה

בבוקר, בסיום רענון הבנקים, לכל חברה:

1. **מושך יתרות ותנועות** מהבנקים.
2. **כותב את תקציר הבוקר** — פסקה אחת מכל הזיכרון של החברה (שהלילה עדכן)
   + המספרים שזה עתה נמשכו.

## 1 · תקציר הבוקר

הפסקה שבעל העסק פוגש ראשון בדשבורד שלו (`docs/cli/dashboard.html`).
החותמת שבפרוטוטיפ היא החוזה: *"מהזיכרון והמספרים — לא מהמקורות הגולמיים"*.

- **הקלט:** מסמכי הזיכרון של החברה + היתרות והתנועות של הבוקר. לא תמלולים,
  לא הודעות.
- **הצורה:** פסקה בשפת הלקוח, עם עוגני jump מהנרטיב אל הווידג׳טים. אדום
  עמוק שמור לסכנה הכספית עצמה בלבד.
- **white-label:** בשם המשרד של היועץ. אין HK ואין מונח פנימי.

## 2 · למה זה ג׳וב נפרד

התקציר צריך את מספרי **הבוקר**, ולכן הוא שייך לג׳וב שהמספרים הם התוצר
שלו. אין תלות־תזמון: הלילה סוגר את התקשורת והזיכרון, הבוקר פותח את
המספרים.

## 3 · כשלים ורענון

- **רענון הבנקים נכשל** — התקציר נכתב מהזיכרון בלבד, עם מספרי אתמול
  מסומנים *"נכון לאתמול"*. לא ממתין ולא נעלם.
- **במהלך היום** — סיכום פגישה שאושר מפעיל כתיבה מחדש של התקציר, עם חותמת
  *"עודכן HH:MM, אחרי …"* — כמו בפרוטוטיפ.

## 4 · צינור ומודל נתונים

```
בסיום רענון הבנקים, פר חברה
──► [B1] משיכת יתרות ותנועות מהבנקים
──► [B2] תקציר הבוקר: כל הזיכרון + המספרים ← פסקה   (AI)
──► [B3] פרסום לדשבורד הלקוח
```

```sql
CREATE TABLE morning_briefs (
  company_id    BIGINT NOT NULL, for_date DATE NOT NULL,
  narrative     JSONB NOT NULL,           -- הפסקה + עוגני jump לווידג׳טים
  numbers_as_of DATE NOT NULL,            -- היום, או אתמול אם הרענון נכשל
  written_at    TIMESTAMPTZ NOT NULL,
  updated_at    TIMESTAMPTZ, updated_reason TEXT,   -- "אחרי פגישת הסקירה"
  PRIMARY KEY (company_id, for_date)
);
```

```
GET  /companies/:id/brief?date                     ← תקציר הבוקר
POST /admin/morning/run   {company_id?, date?}     ← הרצה ידנית
```
